# 简易通量 FluxLite

> **FluxLite 已并入 [FluxEcho](https://github.com/lanStar2003/FluxEcho)（0.8.0 起）。** 这个仓库不再更新。升级时先备份存档，删掉 `fluxlite-*.jar`，换成 [FluxEcho 的最新版](https://github.com/lanStar2003/FluxEcho/releases/latest)；旧存档原样能用，不用任何转换。说明见 [docs/FluxLite.md](https://github.com/lanStar2003/FluxEcho/blob/main/docs/FluxLite.md)。

[![Build](https://github.com/lanStar2003/FluxLite/actions/workflows/build.yml/badge.svg)](https://github.com/lanStar2003/FluxLite/actions/workflows/build.yml)
[![Release](https://img.shields.io/github/v/release/lanStar2003/FluxLite)](https://github.com/lanStar2003/FluxLite/releases/latest)

GTNH 2.8.4（Minecraft 1.7.10，GT5-Unofficial 5.09.51.482）的简化版通量网络。
不建网络、不设密码、不用配置：**GT 无线电网就是网络**，团队成员自动共享。
蒸汽时代就能做出来：电走 GT 无线电网，蒸汽走模组自带的团队蒸汽网络。

## 方块

| 方块 | 作用 |
| --- | --- |
| 通量连接器 | 一个小核心，四周有机器、仓室、线缆或管道就自动伸出连接臂接上，并自动判断方向；电和蒸汽都能走；有连接时自带区块加载 |
| 通量控制中心 | 查看团队所有设备当前的输入输出、实时曲线、排行、单设备详情和告警；有人靠近时在上方浮现全息显示屏（四种大小，可选透明）；可选告警红石输出 |
| 通量终端（物品） | 手持版的控制中心，类似 AE 的无线终端但**不用绑定**：右键打开，任何距离、任何维度都能看团队网络；带在身上还能**无线充电** |

### 方向（以无线电网为视角）

| 相邻 | 方向 | 连接臂颜色 |
| --- | --- | --- |
| 发电机、动力仓 | **输入**：电进入网络 | 绿 |
| 能源仓、耗电机器 | **输出**：网络供电给设备 | 橙 |
| 同时挂着发电和用电设备的 GT 线缆 | **双向** | 蓝 |
| 认不出的 GT 能源设备（其他模组的方块） | **输出**，标签显示「待适配」：用安全的低压包送电，它收多少送多少 | 橙 |
| 能读出连接但没有设备 / GT 机器读不出规格 | 待机 / 无法识别 | 灰 / 红 |
| 被玩家关掉的面 | 已停用 | 深灰 |

接线缆（或管道）的面，名称显示的是线缆另一头的**机器**，不再是线缆本身：一台机器就是它的名字，几台相同的是「名称 ×3」，不同的是「第一台 +2」。只连着一台机器时，控制中心里这一面就代表那台机器（精确计量，「定位」直接指向机器）。

- 连接器界面能改的：**名称**、**每一面的开关**，以及能双向的设备（RF 储能、同时挂着发电和用电设备的线缆或导管等）的**方向**：点方向标签在「自动 → 固定输入 → 固定输出」之间切换，固定后标签前有一把小锁。拆下连接器时这些设置都跟着物品走。
- **电压安全**：供电电压严格等于目标的额定输入；接线缆时取「最弱线缆」与「线缆上最低的机器输入电压」的较小值。读不出规格的设备不会被供电。
- **双向线缆**（同时挂着发电机 / 电池箱和机器的 GT 线缆）像一块聪明的电池，发电机优先：
  - 只收**余电**：线缆上还有机器能收的电包，连接器不收，GT 会把它交给机器。
  - 只**补缺口**：机器的缓存掉到一半以下才补电，而且只补发电机留下的空：一旦发现哪台发电机的电送不出去（机器的收电额度被连接器占了），连接器马上暂停，并把自己的份额降到比刚才少 1 A，过几秒再试着多给 1 A。所以发电机一直满负荷带机器，网络只出差额；发电机没燃料时网络全部接手。线缆上的电池箱不会被网络充电（否则它会马上把电还回来）。
  - **同一时刻只走一个方向**：这一 tick 或上一 tick 往线缆送过电，就不收电；刚收过余电，就不送电。电不会在线缆里来回绕圈。
  - **不会把线缆烧掉**：连接器盯着整条线缆每一段的过载累积（GT 超过额定电流累积到 40 倍就起火），过半就停止送电，降下来再继续。
- 线缆上拆装机器、接上或拆掉线缆，连接器马上重新扫描（拆掉的机器立即从控制中心消失，新机器立即开始供电），并为不是 GT 的设备（AE2 等）重建 GT 的线缆网络。

### 扳手

支持 GT 扳手，以及 BuildCraft、CoFH、AE2、EnderIO、Mekanism、IC2 的扳手（和带 Forge 工具类型 `wrench` 的物品）：

| 操作 | 连接器 | 控制中心 |
| --- | --- | --- |
| 右键 | 点哪一面就开关哪一面 | 转向被点的那一面（点正面、顶面、底面则旋转 90°） |
| 潜行右键 | 像末影流体导管一样拆下，**掉在地上** | 同右键，旋转 |
| 左键挖 | 和 GT 机器一样，扳手很快挖掉，掉在地上 | 和 GT 机器一样，扳手很快挖掉，掉在地上 |

两个方块的采集工具都是扳手（和 GT 机器一样），镐也能挖。不管怎么拆，掉落的物品都保留设置：连接器的名称和关掉的面，控制中心的红石 / 全息投影设置。
右键操作只有所属团队或 OP 可以做；会消耗扳手耐久。

> 用完一组后手里自动补上同样的物品，是 GTNH 自带的 BogoSorter「自动补充」功能，不是本模组做的；不想要可以在 `config/bogosorter.cfg` 里把 `enableAutoRefill` 设为 `false`。

### 供电平稳

GT 本身按「整包」送电：机器缓存有空位才收一整包（电压 × 1A），所以按 tick 看总是一下有、一下没有。连接器的做法与 GT 无线能源仓一样，**每 tick 把机器缓存补满**：

- **直连的 GT 机器 / 仓室**：整安培按额定电压送，剩下不足一包的部分用一个小电压包补上（GT 接受任何不高于额定电压的包），缓存每 tick 正好满，供电量等于机器实际用量。
- **直连的发电机 / 动力仓**：除了 GT 自己推过来的整包，每 tick 再把高于最低存量的余电抽走，所以发电读数也是平稳的；两者合计不超过额定输出。
- **线缆**：保持 GT 原样（线缆的电流上限、损耗、烧线规则都不变），读数用下面的算法消除跳动。

### 「当前」读数怎么算

界面、Waila、全息屏上的「当前 EU/t」按**包与包之间的间隔**计算：取最近至少 20 tick 内的若干个包，用它们的总能量除以首尾间隔。
所以每 16 tick 收一包 32 EU 的机器稳定显示 2 EU/t，不会在 0 和 32 之间跳；开始用电立即显示；停电后几个包的时间内归零。

### 支持的线缆与设备

| 类型 | 方式 |
| --- | --- |
| GT 线缆与机器 | 直接调用 GT 的能量接口；线缆会扫描整条网络（节点上限可配） |
| IC2 导线与机器 | 连接器注册进 IC2 能量网；导线会扫描找出两端设备，输出等级取线上最低耐压 |
| RF 机器与发电机 | CoFH 接口。方向看设备实际怎么做：会往连接器里推电、或能被抽电而不收电的是发电机（输入）；能收电的是机器（输出），收过一次电之后满了也继续算机器。只实现「连接」接口、自己往外推电的引擎（林业、铁路蒸汽引擎、植物魔法等）也能接 |
| EnderIO 能量导管 | 像线缆一样扫描整条导管：上面有机器就**给导管供电**，只有发电机或电容库就从导管收电；导管贴着连接器那一面设成「输入 / 输出」时以导管设置为准。同时有发电机和机器的导管只供电（发电机先供机器，连接器补差额），不会让电在导管里打转 |
| EnderIO 电容库、能量缓存 | 按它自己贴着连接器那一面的 IO 设置（Yeta 扳手切换）：「输入」由网络充电，「输出」和默认（电容库挨着连接器时默认输出）放电进网络 |
| AE2（控制器、能源接收器、充能器、压印器、ME 箱子） | 走 GT EU 接口，每 tick 正好补满它的内部缓存，任何电压都安全；比走 RF 少一成换算损耗。GT 线缆上挂着 AE2 设备也能正常供电 |
| 铁路（电力馈电器、能量装载机） | 走 GT EU 接口，按它还需要多少分包送 |
| 其他实现 GT EU 接口的设备（例如 FluxEcho 的通量灵气汲取台） | 自动检测：设备有公开的 `getInputVoltage()`（可选 `getInputAmperage()`、`getStoredEU()`、`getEUCapacity()`，GT 自己的命名）就按它说的电压送、正好补满；没有就自动设为**输出**，用 `compat.pendingVoltage`（默认 32 V）的小包送，每 tick 最多 `compat.pendingAmperage` 包，它不收的包原样退回。这一面显示「**待适配**」（黄色），表示能用、但还没被正式适配 |
| RF 换算 | 供电按 GT 配置（GTNH 为 100 EU → 360 RF）；收 RF 时**不会比供电更划算**：GTNH 的 GT 配置写的是 100 RF → 100 EU，照搬会让电经 RF 绕一圈变成 3.6 倍，所以收电按 360 RF → 100 EU 计。不足 1 EU 的零头会累积，小太阳能板的电也不会丢 |
| 蒸汽 | 见下一节 |

线缆的「需求」每 tick 按 GT 的收包规则重新计算（缓存没满的机器会再收一包），所以经线缆供电的机器满足率是准的，不会再误报「供电不足」。

### 蒸汽

每个团队有一个**蒸汽网络**：模组自己存（`data/fluxlite_steam.dat`，随世界保存），**没有容量上限**，只能存取蒸汽。和电一样，团队成员共享。

| 相邻 | 方向 |
| --- | --- |
| GT 锅炉（青铜、高压、太阳能、岩浆）、大型锅炉的输出仓、其他模组的锅炉 | **蒸汽输入**：锅炉 → 蒸汽网络（锅炉自己推，连接器也会抽） |
| GT 蒸汽机器（青铜 / 钢）、蒸汽多方块的蒸汽仓、蒸汽涡轮，以及只收蒸汽不收水的设备 | **蒸汽输出**：蒸汽网络 → 机器，按机器能收多少给多少 |
| GT 流体管道 | 像线缆一样扫描：管道上有蒸汽机器就给管道供汽，只有锅炉就从管道收汽 |

- 储罐、普通流体仓这种「什么都收」的设备不会被灌蒸汽。
- 同一面可以同时走电和蒸汽（例如蒸汽涡轮：蒸汽送进去，电收回来），界面里各占一行。
- 每面每 tick 最多搬 `steam.maxLitresPerTick` 升（默认 100 万）。

### 结算

每个面有很小的收集缓冲和供电缓冲。默认**每 tick** 按团队结算一次：先把收集到的电存入无线电网，再补满各面的供电缓冲；余额不够时按需求比例分配。
方块被拆或区块卸载时，缓冲余额立即退回无线电网（在区块存盘前完成，不会重复计算）。

### 区块加载

有连接的连接器加载周围区块（默认半径 1，即 3×3），按区块引用计数、票据池化复用，重启后从注册表恢复。
Forge 默认每个模组 200 张票、每票 25 个区块，不够时会告警，可在 `config/forgeChunkLoading.cfg` 里给 `fluxlite` 调高。

### 无线充电

背包里带着通量终端，身上的电动物品就从团队的 GT 无线电网充电：

- **潜行右键**终端开关充电，默认开着；终端的提示里写着现在是开还是关。
- 每秒一轮，充背包（快捷栏和背包）和盔甲栏里没满的电动物品：GT 和 IC2 的工具、电池、护甲**不限电压等级**，RF 物品（EnderIO、龙研等）按 GT 配置的 EU → RF 换算。
- 余额不够时按余额充，快捷栏在前、背包在后；网络一点都不会透支。
- 充掉的电算进团队的输出，控制中心的总览和曲线里能看到。
- 服务器可以在配置里关掉，或者限制每人每秒最多充多少 EU、要不要给电池和护甲充、要不要充 RF 物品。

## 控制中心

| 页面 | 内容 |
| --- | --- |
| 总览 | 输入 / 输出 / 净值（当前 EU/t）、无线电网余额与耗尽预估、能量流曲线（实时 10 秒，或 1 小时 / 24 小时平均）、用电最多与发电最多 |
| 设备 | 每个面（精确计量）和线缆后面的每台 GT 机器（`~` 开头，读 GT 自身统计）。筛选：方向（全部 / 输入 / 输出 / 双向）、状态（运行中 / 空闲 / 离线 / 已关闭 / 无法识别，带数量）、电压等级、所属连接器、类型（直连设备 / 线缆 / 线缆后的机器），加搜索和一键清除；点表头排序、滚轮翻动；底部显示筛选结果的数量与合计输入输出；点一行看详情 |
| 详情 | 当前值、1 小时峰值和发生时间、供电满足率、运行时间占比、累计和今日、实时 / 1 小时 / 3 天曲线、24 小时分布、线缆后机器的缓存占比、定位高亮 |
| 告警 | 余额过低、耗尽预估过短、供电不足、负载过高、长时间无流动、区块加载失败、无线电网不可用。**默认关闭**，在设置页或告警页打开 |
| 设置 | 告警开关（默认关）；聊天提示（默认关）；红石输出；全息投影的开关、大小（小 / 中 / 大 / 特大）和透明背景 |

团队用到蒸汽时，总览页多一行蒸汽网络（储量、输入、输出、净值），点开看曲线；设备页的「类型」可以筛出蒸汽设备，数值单位是 L/t。

通量终端打开的是同一个界面；全息投影和红石输出属于控制中心方块，只能在方块上改。

### 全息显示屏

玩家走到控制中心附近（默认 12 格，可配置）时，顶部的投影镜头射出一道光，一块全息面板在方块上方展开：先是一条亮线横向拉开，再纵向展开成玻璃面板，内容闪烁着浮现；走远后折叠收起。面板朝向和控制中心的屏幕一致，轻微上下浮动，从背面只看到玻璃。

面板内容参考 GTNH 的工业信息面板：团队状态（正常 / 告警数 / 电网不可用）、网络余额、净流量与耗尽预估、输入 / 输出、蒸汽网络（用到时）、最近 10 秒曲线、连接器在线数。
在控制中心的「设置」页可以选大小：小（约 2.3 格宽）、中、大、特大（约 7 格宽），越大能从越远处看到；也可以关掉「透明背景」，换成不透明的面板，更容易看清。
数据每 0.5 秒只发给范围内的玩家；所属团队可以关掉投影，服务器可把 `hologramRange` 设为 0 全部关闭。

光影（Angelica + 光影包）下：投影和水、玻璃一起在半透明阶段绘制，面板写入深度，所以光影不会把它当成后面的天空或方块（以前白天会透出背景）；只用方块光照亮，不受日光和阴影影响，也不投下影子。绘制完会正确恢复贴图状态，不会再让附近的箱子等方块实体变成白色。

OP 可以在控制中心切换查看所有团队。统计的分钟级、小时级和累计值存在 `data/fluxlite_registry.dat`，重启后保留。

## 配方

蒸汽时代就能做，全部是工作台配方（小写字母是 GT 工具：w 扳手、d 螺丝刀）。可在配置里关闭，改用 CraftTweaker 脚本。

| 物品 | 配方 | 材料 |
| --- | --- | --- |
| 通量连接器 ×2 | `PRP` / `EHE` / `PwP` | P 青铜板，R 红石，E 末影珍珠，H 青铜机器外壳 |
| 通量控制中心 | `GGG` / `RHR` / `PdP` | G 玻璃板，R 红石，H 青铜机器外壳，P 青铜板 |

## 配置

`config/fluxlite.cfg`：无线充电（`charging.enabled`、`charging.intervalTicks`、`charging.maxEuPerSecond`（0 = 不限）、`charging.batteries`、`charging.armor`、`charging.rf`）、结算周期（默认 1 tick）、无线损耗（默认 0）、每团队连接器上限、区块加载开关 / 半径 / 离线策略、线缆扫描节点上限与重扫间隔、告警阈值、是否注册默认配方、RF 名义电压、待适配设备的送电电压和每 tick 包数（`compat.pendingVoltage`、`compat.pendingAmperage`）、全息显示屏范围（`display.hologramRange`，0 = 关闭）、蒸汽开关与每面每 tick 上限（`steam.enabled`、`steam.maxLitresPerTick`）。

在 [Releases](https://github.com/lanStar2003/FluxLite/releases) 页面下载 `fluxlite-<版本>.jar`，放进 GTNH 实例的 `mods` 文件夹。`-dev` 和 `-sources` 两个 jar 是给开发用的。

## 构建

需要 JDK 25（`.java-version`）：

```bash
./gradlew build
```

产物在 `build/libs/fluxlite-<版本>.jar`；版本号取自 git 标签；也可以用 `VERSION=0.5.0 ./gradlew build` 指定。

推送到 `main` 时，GitHub Actions 会自动构建并跑测试，jar 和界面预览图作为构建产物上传。
推送版本标签（如 `0.4.0`）会自动构建并发布 Release，发布说明取自 [CHANGELOG.md](CHANGELOG.md) 的对应小节：

```bash
git tag 0.5.0 && git push origin 0.5.0
```

界面、方块模型和全息显示屏可以不进游戏预览：`./gradlew test` 会用原版字体把它们渲染到 `build/previews/*.png`（`holo_scene.png` 是控制中心加全息屏的等轴视图，`holo_glass_vs_solid.png` 对比透明和不透明背景，`terminal_*.png` 是通量终端）。
